Прочитай документ задачи и связанные решения проекта. Без пути выполни [handoff](../handoff/SKILL.md) по текущему разговору. Нерешённое согласуй по [grilling](../grilling/SKILL.md); не добавляй продуктовые решения при разбиении.

Каждая задача даёт самостоятельно проверяемый результат через необходимые слои и помещается в одну сессию исполнителя. Не дели фичу механически на API, UI и тесты. Общие подготовительные изменения выделяй только при реальной необходимости. Укажи зависимости, которые действительно блокируют работу; граф не должен содержать циклов.

Широкое механическое изменение, которое нельзя проверить отдельными частями, оставь одной задачей. Разбивай миграцию на совместимые этапы только если такая стратегия уже согласована.

Покажи разбиение: результат каждой задачи, критерии приёмки и зависимости. Обоснованное и дешёвое решай сам по grilling; спорные границы и зависимости согласуй до сохранения.

В каталоге документа задачи создай каталог `tickets/`, по файлу NN-<slug>.md на задачу, зависимости раньше зависимых. Общие решения и дословные записи не копируй: ссылайся на исходный документ и указывай относящиеся к задаче пункты. Точный путь нужен для навигации, предлагаемые файлы реализации не превращай в обязательный контракт.

```md
# NN: Название

Документ задачи: <относительная ссылка>
Результат: <наблюдаемое поведение или проверяемое изменение>
Зависит от: <номера задач или «нет»>
Статус: готова / заблокирована / выполняется / выполнена

## Критерии приёмки

- <проверяемое требование из согласованной задачи>

## Проверка

- <через какой интерфейс и какими сценариями подтвердить результат>
```

В исходном документе добавь ссылки на тикеты. При повторном вызове актуализируй существующий набор, сохраняя выполненное; не создавай дубликаты. Не создавай issues, PR и коммиты. Итог — пути к задачам и порядок выполнения.
