Проверь план так, чтобы `implement` выполнил его без вопросов и ошибок. План — в разговоре; если в аргументах путь к документу, проверяй его, включая расхождения с разговором.

До работы прочитай [grilling](../grilling/SKILL.md).

Направления:

- Факты: пути, функции, константы и поведение, названные существующими, — сверь с кодом; помеченное «(не проверено)» — первым, подтвердилось — сними пометку. Причины решений проверь на граничных значениях: ноль, пусто, один элемент, максимум, который принимает код. Причина не подтвердилась — переоткрой само решение вопросом, а не только его формулировку.
- Полнота: у новых данных и запросов решены состояния loading / empty / error; у каждого решения есть проверка — сценарий в «Швах» или правило дословной записи; границы и отклонённое не пролезают обратно; сценарии «Швов» — из разговора, не новое поведение; правки документов проекта — дословно, с файлом и местом.
- Простота: решения соразмерны задаче — нет слоёв, обобщений, параметров, настроек и сценариев, которых задача не требует; нет самописного там, где есть утилита проекта, библиотеки или платформы. Есть более простое или очевидное решение, которое проходит те же сценарии «Швов», — предложи его: что убрать или чем заменить и почему оно проще (меньше мест, кода, состояний).
- Правила проекта: инструкции агенту, документы о терминах, решениях и спеке, линтеры и хуки; сознательное отступление названо.
- Проверяемость: через что проверять результат, покрыты ли пограничные случаи новых входов и ветвей.
- Имена — каждое новое: grep по коду и документам — не значит уже другое, не из «Избегать» словаря; одно понятие — одно имя в коде, словаре и спеке.

Правь только то, из-за чего `implement` ошибётся, остановится с вопросом или внесёт регрессию, и переусложнённое из направления «Простота». Детали, которые `implement` выберет сам по соседнему коду (имена, сигнатуры, тексты справки, файлы тестов), стиль, пунктуацию и форму ссылок не трогай. Находки — по правилам `grilling`: обоснованное кодом или документами исправь сам и покажи в «Решено по умолчанию». Вопросом — всегда:

- изменение смысла решения, имени или записи, которые дал или принял пользователь;
- новое поведение, без которого `implement` ошибётся: это решение, а не исправление;
- упрощение, которое меняет решение, а не только устройство кода.

Проблемы, которые были до задачи и которых она не касается, — строкой «Вне задачи» в ответе, в план не вноси. Поведение, которое задача добавляет, ломает или делает неверным (валидация нового входа, сообщения, регрессии), — не вне задачи. Подтвердившееся не перечисляй.

Документ правь на месте, заменяя, без следа проверки; без документа — формулировки в ответе. Код не трогай.

Команды следующих шагов показаны для Codex (`$имя`). В Claude Code замени префикс каждого вызова на `/`, включая вложенный вызов: `$ask-agents $review-changes` → `/ask-agents /review-changes`.

Когда открытых вопросов нет — предложи `$implement <путь>`; без документа — `$implement`. Отдельным fenced-блоком без языка.
