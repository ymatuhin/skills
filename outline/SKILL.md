Согласуй задачу так, чтобы по итогу разговора `implement` мог её выполнить.

Вызови skill `grilling`, `domain-modeling` и `spec-writing`.

Записи для документов проекта (словарь, спека, ADR, README) не пиши в файлы — отдавай внутри раунда `grilling`: вопросом, если это ADR, есть выбор или запись меняет действующее правило; иначе строкой в «Решено по умолчанию». В записи — файл, действие (создать, добавить, заменить, удалить), якорь (термин или заголовок пункта) и итоговый текст целиком, в форме окружающего текста (пункт списка, строка прозы). Перед выводом перечитай каждый пункт затронутых документов: пункт, который после задачи станет неверным, — запись «заменить» в этом же раунде. Сверь записи между собой, с решениями раунда и со словарём, включая записи этого раунда: якорь существует, слов из «Избегать» нет, одно правило — одна формулировка. В следующем раунде выводи только изменённые записи.

Ничего не меняй в текущем каталоге, в том числе командами проекта.

Команды следующих шагов показаны для Codex (`$имя`). В Claude Code замени префикс каждого вызова на `/`, включая вложенный вызов: `$ask-agents $review-changes` → `/ask-agents /review-changes`.

Когда открытых вопросов нет — предложи `$handoff` или `$implement`. Каждую команду выводи отдельным fenced-блоком без языка.
