# Процесс работы со скилами

Пользователь принимает существенные решения; агент изучает код, делает работу и проверяет её. Скилы можно вызывать отдельно; связывает их каталог задачи в `/tmp/handoffs` с документом передачи `handoff.md`.

## Маршрут

| Задача          | Маршрут                                                                                                    |
| --------------- | ---------------------------------------------------------------------------------------------------------- |
| Фича, изменение | `/outline` → `/handoff` → новая сессия (worktree): `/review-plan <путь>` → `/implement <путь>` → новая сессия: `/review-changes <путь>` → при находках `/implement <путь>` и снова ревью → `/ship <путь>` |
| Баг             | `/debug` → исправление на месте → `/review-changes` → `/ship`; крупное — `/handoff` → тот же хвост                 |

- `/outline` ничего не меняет и файлов не создаёт: раунды вопросов через `grilling` — В1, В2… с рекомендацией первой; «Ок/+» принимает рекомендации и решения по умолчанию. Итога не выводит; когда открытых вопросов нет — предлагает `/handoff` или `/implement`.
- `/debug` уточняет симптом, воспроизводит минимально, проверяет гипотезы по одной с предсказанием и доказательством, исправляет через `tdd`; решения об исправлении — по правилам `grilling`. В конце удаляет исследовательские правки.
- `/to-tickets <путь>` сохраняет задачи реализации с критериями приёмки и зависимостями отдельными файлами в `tickets/` каталога задачи. Общие решения остаются в исходном документе.
- `/handoff` сжимает разговор в `/tmp/handoffs/<yyyy-mm-dd>-<slug>/handoff.md`; в том же каталоге хранятся тикеты. Выводит команды `/review-plan <путь>` и `/implement <путь>`.
- `/review-plan` проверяет план из разговора или документа: факты против кода, полнота, правила проекта, границы, проверяемость, имена (соглашения, занятость, точность, согласованность). Обоснованное правит в документе сам, спорное спрашивает; код не трогает. С документом параллельно запускает внешнего ревьюера — другого агента (из Claude Codex, из Codex Claude) — и согласует его находки как свои. Когда открытых вопросов нет — предлагает `/implement <путь>`; без документа — `/implement`.
- `/implement` выполняет задачу в текущем дереве; решения вне документа, отклонения от плана и пограничные случаи — по правилам `grilling`; использует `tdd` при изменении поведения, проверяет точечно затронутые файлы. Отмечает шаги в документе, без документа — в итоговом сообщении. Исправляет пункты «ожидает» из «Находок ревью». Ответ начинает с объяснения по `show-me`, как работает затронутая часть системы и что изменилось. Не коммитит.
- `/review-changes` проверяет изменения по направлениям (корректность, правила и спека, читаемость, границы, устойчивость, тесты, безопасность). Код не правит: находки — по правилам `grilling`, принятые остаются в `final.md` со статусом «ожидает», в документе — ссылка разделом «Находки ревью»; параллельно запускает внешнего ревьюера — другого агента (из Claude Codex, из Codex Claude) — и согласует его находки как свои. Дальше — `/implement` для исправлений и повторное ревью, без находок — `/ship`.
- `/ask-agents <задача>` выполняет задачу на чтение и анализ сам и параллельно поручает её другому агенту через `ask-agents/run.sh`: из Claude — Codex (`codex exec`), из Codex — Claude (`claude -p`), в своей модели по умолчанию с high effort, read-only. Хост скрипт определяет по `CLAUDECODE` / `CODEX_THREAD_ID` (`CODEX_SESSION_ID`); не определил — запускает обоих. Работа — по `ask-agents/PROTOCOL.md`: независимые отчёты во временных файлах, сверка, раунд перекрёстной проверки в той же сессии внешнего агента (`run.sh --resume`), итог `final.md` с пометками «Codex» / «Claude» / «оба»; правит хост по правилам `grilling` и обновляет статусы в `final.md`. Прогон агента ограничен 20 минутами; не сработавший агент — сообщение одной строкой, работа продолжается.
- Внешний ревьюер `/review-changes` и `/review-plan <путь>` — другой агент, запускается тем же `ask-agents/run.sh --skill`. Он запускает тот же скил с `--external-reviewer`: отвечает отчётом и вердиктами по протоколу и внешних ревьюеров не запускает. Сверка, перекрёстная проверка, `final.md` и сбои — по `ask-agents/PROTOCOL.md`; правит и спрашивает основная сессия по `grilling`. Ревьюер не видит разговор, поэтому у `/review-plan` — только с документом.
- `/ship` — только по явному запросу: полные проверки один раз, коммиты только с изменениями задачи, push в текущую ветку; на основную ветку не пушит — спрашивает.
- `/retro` разбирает текущую или указанную сессию: предлагает подтверждённые улучшения навигации, проверок, инструкций и работы с инструментами; файлы не меняет.

Без пути каждый скил работает по аргументам и контексту разговора. Команду следующего скила каждый выводит отдельным fenced-блоком без языка; по одной команде на блок.

## Постоянные документы

| Документ     | Назначение                                                  | Кто формулирует                                                       | Формат                              |
| ------------ | ----------------------------------------------------------- | --------------------------------------------------------------------- | ----------------------------------- |
| `GLOSSARY.md` | термины домена                                              | `domain-modeling` в раундах `/outline`; в `/review-changes` — как исправление | запись в `domain-modeling/SKILL.md` |
| `docs/adr/`  | причины неочевидных решений; только с согласия пользователя | `domain-modeling` в раундах `/outline` и `/review-changes`, вопросом В-N      | `domain-modeling/ADR-FORMAT.md`     |
| `SPEC.md`    | принятые продуктовые решения проверяемыми утверждениями     | `spec-writing` в раундах `/outline`                                   | шаблон в `spec-writing/SKILL.md`    |

`grilling`, `domain-modeling` и `spec-writing` не вызываются пользователем и друг о друге не знают: каждый описывает только своё поведение, связывает их вызывающий скил. `grilling` — формат и критерии вопросов (В-N, «Ок/+», «Решено по умолчанию»; факты ищет агент; обоснованное и дешёвое решает сам и показывает списком, дорогое, необоснуемое и конфликтующее с принятым спрашивает); его загружают `/outline`, `/review-plan`, `/implement`, `/review-changes`, `/debug`, `/ship`, `/to-tickets`, `/ask-agents` и `tdd`. `domain-modeling` и `spec-writing` сами по себе пишут файлы; `/outline` загружает их и переводит записи в раунды `grilling`; `/review-changes` загружает `domain-modeling` и выдаёт записи как находки — вопросом В-N или строкой «Решено по умолчанию» с файлом, действием, якорем и итоговым текстом. `/handoff` переносит такие записи дословно, в репозиторий они попадают через `/implement`. `tdd` загружают `/implement` при изменении поведения и `/debug` для исправления; швы вне задачи он согласует через `grilling`.

## Прочее

- `frontend-design`, `teach` — сторонние скилы, к маршруту не относятся.
- Скиллы рабочего процесса адаптированы на основе набора [Matt Pocock — mattpocock/skills](https://github.com/mattpocock/skills). Названия, форматы документов и инструкции изменены под местный процесс; атрибуция относится ко всему этому набору, а не только к `retro` и `to-tickets`. Последние добавлены по [версии 1.3.1](https://github.com/mattpocock/skills/tree/v1.3.1/skills/engineering).
- `show-me` — сокращённая русская адаптация скилла [HumanLayer show-me](https://github.com/humanlayer/skills/blob/main/plugins/show-me/skills/show-me/SKILL.md). Объясняет изменения визуально; используется в итоге `/implement` — как работает система после изменений, — при подготовке PR и для сложных находок ревью.

## Репозиторий

`~/.claude/skills` — git-репозиторий [ymatuhin/skills](https://github.com/ymatuhin/skills); правки скилов фиксируются коммитами.

Установка на новой машине:

```bash
git clone git@github.com:ymatuhin/skills.git ~/.claude/skills
```

```bash
~/.claude/skills/sync-links.sh
```

- Скил — каталог с `SKILL.md` (frontmatter `name`, `description`) и вспомогательными файлами, на которые он ссылается.
- `agents/openai.yaml` — настройка для Codex: `allow_implicit_invocation: false`, скил запускается только явной командой.
- `sync-links.sh` — симлинки `~/.codex/skills` → `~/.claude/skills` (источник — claude). Идемпотентен: досоздаёт недостающие, удаляет битые, сообщает о файлах, которые есть только в Codex. Запускать после добавления или удаления скила.
- `.trash/` и `.DS_Store` в `.gitignore`.
