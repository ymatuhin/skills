Выбери самое простое представление, которое объясняет суть. Без вступления; пояснение короткое, рядом с визуализацией.

- Логика и алгоритм — псевдокод.
- Порядок вызовов — дерево вызовов.
- UI и границы состояния — дерево компонентов.
- Ответственность файлов — неглубокое дерево каталогов.
- Взаимодействия, данные и переходы состояний — Mermaid.
- Изменение знакомой структуры — diff; почти целиком новый блок — целиком.

Оставляй только нужные для объяснения вызовы, файлы, состояния и границы. Не используй все формы сразу. Имена и связи сверяй с кодом; неизвестное помечай, не достраивай схему догадками.

Для PR показывай окончательное изменение после исправлений. После реализации показывай, как работает затронутая часть системы и что изменилось. В ревью визуализируй сложную находку, когда схема помогает понять причину; простой находке достаточно файла, строки и объяснения. Схема не заменяет проверки кода.

Если Mermaid недостаточно для сравнения UI или сложной композиции, создай один HTML-файл: схема, инфографика или короткая презентация. Используй реальные подписи и данные, стиль продукта, поддержи мобильный экран. Сохрани вне репозитория, если файл не является результатом задачи, и открой доступным инструментом просмотра. В Markdown-описании PR используй представление, которое поддерживает трекер.
